## DELIVERABLE 1 -- weekly.yml Fix

### Root Cause Analysis

Three confirmed structural bugs in the original weekly.yml:

**BUG 1 (confirmed): --step a05 maps to a non-existent step ID**

pre_market_runner.py has 20 registered step IDs. The ID a05 is not in this list.
Registered IDs: health_check, ohlcv_update, fix_volumes, earnings_cal, data_quality,
a03_bench, a03, tvremix_us, a03c, fwd_estimates, fill_ohlc, data_quality_eod,
ohlcv_prefetch, rs_history, s4_brain, s4_qqq_sync, s4_obsidian, s4_postmortem,
pulse_us_best_final, pulse_us_daily.

When step_filter finds no match, run_pipeline() returns {} (empty dict). Python treats
{} as falsy so sys.exit(1) never fires. Step 4 shows green in CI but rs_theme_ranker.py
never ran in 89 consecutive weekly runs.

Root issue behind the root issue: scripts/pre_compute/rs_theme_ranker.py source has been
deleted. Only the compiled bytecode (scripts/pre_compute/__pycache__/rs_theme_ranker.cpython-312.pyc)
remains. The step cannot run until source is recovered from git history or rewritten.

Impact: data/rs_universe/theme_rs_latest.json and data/themes/ have never been rebuilt
by the weekly job. Every premarket run reading theme RS data operates on stale/missing files.

**BUG 2 (confirmed): data/ohlcv_cache/ is gitignored**

.gitignore line: data/ohlcv_cache/  # Legacy v1 file-based OHLCV cache

The original weekly.yml Step 2 ran --step ohlcv_prefetch, which wrote to data/ohlcv_cache/.
The commit step then tried git add data/ohlcv_cache/ -- silently added nothing.
Each run re-fetched ~5,000 tickers from Yahoo Finance (~21 min) and discarded all results.
This is the most likely cause of the 89 consecutive red X: the ohlcv_prefetch step hitting
Yahoo rate limits on 5,000 tickers with no cache persistence, eventually timing out or
throwing an unhandled exception.

**BUG 3 (cosmetic): Alert hardcoded to universe_builder.py failed**

The if: failure() alert step always sent "universe_builder.py failed" regardless of which
of the 4 steps actually failed. Made remote diagnosis from Telegram impossible.

### What Was Fixed

Fixed .github/workflows/weekly.yml:

1. Removed --step ohlcv_prefetch (old Step 2) -- gitignored output, ~21 min wasted per run,
   no lasting artifact. Core purpose of weekly job is RS benchmark, not OHLCV pre-fetch.

2. Removed --step a05 (old Step 4) -- source file rs_theme_ranker.py is deleted. Cannot
   run until source is restored.

3. Removed data/ohlcv_cache/ from mkdir -p and git add -- gitignored.

4. Fixed alert message -- now says weekly benchmark job failed generically.

5. Left Steps 1 and 2 (universe_builder.py and a03_bench) intact.

### Remaining Required Before weekly.yml Is Complete

    git log --all --full-history -- scripts/pre_compute/rs_theme_ranker.py
    git show <commit>:scripts/pre_compute/rs_theme_ranker.py > scripts/pre_compute/rs_theme_ranker.py

Then: register as step id: a05 in pre_market_runner.py STEPS list.
Re-add Step 4 to weekly.yml as: python scripts/runners/pre_market_runner.py --step a05
Add data/rs_universe/theme_rs_latest.json + data/themes/ to the commit step.

## DELIVERABLE 3 -- Full Data Flow Documentation

### 1. Data Sources

| Source | What | Frequency | Credentials |
|--------|------|-----------|-------------|
| TVRemix | SET stock OHLCV + real SET index | Daily EOD after 16:30 ICT | TVREMIX_API_KEY |
| Yahoo Finance query2/.query1 | .BK ticker OHLCV fallback | On-demand | None |
| Investing.com (direct fetch) | SET level for regime gate | On-demand | None |

Rate limits: TVRemix free beta: 20/min, 200/hr, 1500/day.

### 2. Storage -- thai_ohlcv.db

File: data/research/thai_ohlcv.db (71 MB, committed to git)

    thai_ohlcv              -- price history (ticker+date PK, open, high, low, close, volume)
    set_index_history       -- real SET composite (date PK, set_close)
    entry_screen_column_order  -- signal column registry
    entry_screen_signals    -- packed bool blob (date+ticker PK, regime, n_cols, signals_packed)

Storage: 2613 bool cols packed as numpy.packbits() = 327 bytes/row. 39k rows = ~12.8 MB (was 877 MB CSV).

### 3. Compute Pipeline

DAILY (cron-job.org triggers workflow_dispatch):

  10:30 UTC (17:30 ICT) -- thai_eod_update.yml
    scripts/ci/th_eod_set_index.py
      -> thai_data_layer.update_set_index_history()
      -> writes set_index_history rows to thai_ohlcv.db
      -> git commit + push

  00:00 UTC (07:00 ICT next day) -- thai_paper_trade.yml
    scripts/research/thai_paper_trader.py
      -> reads thai_ohlcv + set_index_history
      -> computes RS rankings (COMBINED: rs_days=21, top_n=10, vol_weight)
      -> rebalances every 5 trading days
      -> writes thai_paper_portfolio.json + thai_paper_log.json
      -> sends Telegram [TH] summary

  09:30 UTC (16:30 ICT) -- thai_watchdog.yml
    scripts/research/thai_data_watchdog.py
      -> checks thai_ohlcv staleness (TDEX.BK proxy)
      -> Telegram alert if data > 2 trading days stale

WEEKLY (manual / on-demand):
  python scripts/research/thai_data_layer.py --update   # incremental OHLCV
  python scripts/research/thai_data_layer.py --init     # first-time bulk (~20 min)

### 4. Entry Screen Signals

thai_entry_screen.py computes ~2613 boolean signals per (date, ticker) bar and writes
them to entry_screen_signals via entry_screen_db.write_entry_screen() as packed numpy
bitfields (327 bytes per row).

Signal build order:
  1. thai_entry_screen.py     -- base signals (MA crossovers, breakouts, volume surges, momentum)
  2. thai_add_rs_signals.py   -- appends RS-based signal columns
  3. thai_add_combo_signals.py / _r2.py  -- appends backtest-validated combo signals

entry_screen_column_order preserves column order for correct unpackbits() decoding on read.
Q-signals validated as of 2026-09-13: 825 total.
Best: Q872/Q916 (I4+A3+FVG h3=100%), Q883/Q886 (CHOCH h3=88.9% both days).

### 5. PULSE Daily

  thai_pulse_daily.py:
    1. read_entry_screen(date=today) from entry_screen_signals
    2. Load q_library_th.json (pattern library from build_q_library_th.py)
    3. Score each ticker: sum of firing Q-signal hit-rate weights
    4. Rank and write thai_pulse_output.json
    5. Telegram top 5
